# Каталог use case'ов (отрасль)

ID и описание — **язык студии**, без экранов MyWay. Частота: **день** / **неделя** / **редко**.

---

## UC-OWNER — владелец

### UC-OWNER-01 — Утренний срез бизнеса
- **Актёр:** владелец
- **Триггер:** утро, перед звонками
- **Шаги:** открыть сводку (вчера/неделя): выручка, новые клиенты, загрузка залов, долги арендаторов
- **Данные:** агрегаты финансов, KPI
- **Частота:** день
- **Боль:** узнаёт о проблеме из Excel админа с задержкой

### UC-OWNER-02 — Утвердить тарифы и абонементы
- **Актёр:** владелец
- **Триггер:** сезон, конкурент снизил цены
- **Шаги:** изменить цены абонементов, пробного, аренды; сообщить админам
- **Данные:** шаблоны абонементов, ставки залов
- **Частота:** редко
- **Боль:** админы продают по старым ценам

### UC-OWNER-03 — Нанять администратора
- **Актёр:** владелец
- **Триггер:** расширение, новый филиал
- **Шаги:** создать учётку, выдать доступ в CRM, обучить смену/кассу
- **Данные:** staff, права
- **Частота:** редко
- **Боль:** новый админ видит финансы без ограничений

### UC-OWNER-04 — Разрешить админу видеть финансы
- **Актёр:** владелец
- **Триггер:** управляющий в отпуске
- **Шаги:** расширить права старшего админа на отчёты и оборот
- **Данные:** permission / флаг
- **Частота:** редко
- **Боль:** либо всё, либо ничего

### UC-OWNER-05 — Закрыть месяц с бухгалтером
- **Актёр:** владелец + бухгалтер
- **Триггер:** 1-е число
- **Шаги:** выгрузить продажи/расходы, сверить с кассой, передать в 1С
- **Данные:** экспорт, категории, счета субаренды
- **Частота:** месяц (редко в дневном цикле)
- **Боль:** ручная сборка из CRM + Excel

### UC-OWNER-06 — Решение по убыточному направлению
- **Актёр:** владелец
- **Триггер:** низкая заполняемость группы
- **Шаги:** аналитика по направлению/залу/преподавателю → закрыть слот или сменить тренера
- **Данные:** посещаемость, оборот по группировке
- **Частота:** неделя
- **Боль:** нет разреза «зал / преподаватель / направление»

## UC-MANAGER — управляющий филиалом

### UC-MANAGER-01 — Планирование недели
- **Актёр:** управляющий
- **Триггер:** пятница
- **Шаги:** проверить расписание, дубли залов, отпуска преподавателей, брони арендаторов
- **Данные:** календарь залов
- **Частота:** неделя
- **Боль:** конфликт аренды и группы в одном зале

### UC-MANAGER-02 — Контроль плана продаж
- **Актёр:** управляющий
- **Триггер:** середина месяца
- **Шаги:** CRM: пробные → абонементы; планёрка с админами
- **Данные:** конверсия, KPI
- **Частота:** неделя
- **Боль:** CRM не связана с планом

### UC-MANAGER-03 — Эскалация жалобы клиента
- **Актёр:** управляющий
- **Триггер:** недовольный родитель / арендатор
- **Шаги:** история клиента, компенсация (отработка/скидка), фиксация в CRM
- **Данные:** клиент, абонемент, заметки
- **Частота:** неделя
- **Боль:** нет единой истории обращений

### UC-MANAGER-04 — Утвердить замену преподавателя
- **Актёр:** управляющий
- **Триггер:** болезнь тренера
- **Шаги:** найти замену в расписании, уведомить группу, отметить substitute
- **Данные:** слот, staff, уведомления
- **Частота:** неделя
- **Боль:** клиенты не знают о замене

## UC-FRONTDESK — администратор ресепшена

### UC-FRONTDESK-01 — Открытие студии
- **Актёр:** администратор
- **Триггер:** начало смены
- **Шаги:** включить свет/музыку, проверить чистоту, открыть кассу, проверить расписание дня
- **Данные:** смена кассы, расписание
- **Частота:** день
- **Боль:** нет чек-листа «открытие» в системе

### UC-FRONTDESK-02 — Обработка входящего звонка
- **Актёр:** администратор
- **Триггер:** звонок «хочу на пробное»
- **Шаги:** консультация → записать в CRM → назначить пробное → SMS подтверждение
- **Данные:** лид, слот, клиент
- **Частота:** день
- **Боль:** забыл записать — лид потерян

### UC-FRONTDESK-03 — Продажа абонемента на ресепшене
- **Актёр:** администратор
- **Триггер:** клиент после пробного
- **Шаги:** выбор программы → договор → оплата → активация абонемента в CRM
- **Данные:** абонемент, оплата, клиент
- **Частота:** день
- **Боль:** ручная активация, ошибка в остатке посещений

### UC-FRONTDESK-04 — Check-in посетителя
- **Актёр:** администратор
- **Триггер:** клиент пришёл на занятие
- **Шаги:** найти клиента → проверить абонемент → отметить визит / QR
- **Данные:** посещение, списание с абонемента
- **Частота:** день
- **Боль:** очередь на ресепшене

### UC-FRONTDESK-05 — Заморозка абонемента
- **Актёр:** администратор
- **Триггер:** клиент на больничном / отпуск
- **Шаги:** проверить правила → заморозить в CRM → продлить срок
- **Данные:** абонемент, freeze
- **Частота:** неделя
- **Боль:** спор «сколько дней можно»

### UC-FRONTDESK-06 — Отработка пропущенного занятия
- **Актёр:** администратор
- **Триггер:** клиент пропустил по уважительной причине
- **Шаги:** записать на другой слот группы / индивидуально без списания
- **Данные:** записи, абонемент
- **Частота:** неделя
- **Боль:** нет явного типа «отработка»

### UC-FRONTDESK-07 — Закрытие студии и кассы
- **Актёр:** администратор
- **Триггер:** конец смены
- **Шаги:** сверка наличных/терминала с CRM, Z-отчёт, закрытие смены
- **Данные:** касса, продажи дня
- **Частота:** день
- **Боль:** CRM ≠ факт кассы

### UC-FRONTDESK-08 — Запись клиента из Instagram
- **Актёр:** администратор
- **Триггер:** DM «запишите на субботу»
- **Шаги:** создать клиента → слот → подтверждение
- **Данные:** клиент, record
- **Частота:** день
- **Боль:** двойная бронь с виджетом

### UC-FRONTDESK-09 — Напоминание о продлении
- **Актёр:** администратор (или авто)
- **Триггер:** абонемент заканчивается через 3 дня
- **Шаги:** звонок / SMS → предложить продление
- **Данные:** абонемент, уведомление
- **Частота:** день
- **Боль:** нет авто-списка «заканчиваются»

### UC-FRONTDESK-10 — Оформление аренды зала (разовый)
- **Актёр:** администратор
- **Триггер:** звонок арендатора
- **Шаги:** свободный слот → цена → предоплата → бронь
- **Данные:** sublease booking, оплата
- **Частота:** день
- **Боль:** пересечение с группой в календаре

### UC-FRONTDESK-11 — Одобрение заявки с сайта
- **Актёр:** администратор
- **Триггер:** новая заявка «стать учеником»
- **Шаги:** проверить → одобрить → клиент получает доступ
- **Данные:** join request, user
- **Частота:** неделя
- **Боль:** заявки теряются в почте

### UC-FRONTDESK-12 — Waitlist на переполненную группу
- **Актёр:** администратор
- **Триггер:** группа full, клиент хочет записаться
- **Шаги:** добавить в лист ожидания → при отмене — авто-предложение
- **Данные:** waitlist, record
- **Частота:** неделя
- **Боль:** вручную в блокноте

- **Шаги:** перенос в ЛК → новый слот
- **Данные:** booking reschedule
- **Частота:** неделя

### UC-RENTER-04 — Получение ключа / доступ

### UC-RENTER-05 — Оплата счёта по субаренде
- **Актёр:** арендатор
