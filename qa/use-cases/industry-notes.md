# Выжимки отрасли: CRM, вакансии, аренда залов

Конспект источников для каталога ролей и use case'ов. Не копия ТЗ вендоров — обобщение того, как студии **реально** делят работу и данные.

## 1. CRM и автоматизация (RU / global)

### YCLIENTS

- **Аудитория:** салоны, йога, танцы, фитнес; «всё в одном»: записи, склад, зарплаты, аналитика.
- **Роли в маркетинге:** владелец (видит бизнес), тренер (расписание + заработок), администратор (обслуживание в N раз быстрее).
- **Абонементы:** автоактивация, заморозка, списание посещений, напоминания об окончании — без ручной работы админа.
- **Права:** настраиваемые права доступа на каждого сотрудника; мобильное приложение для владельца.
- **Коммуникация:** SMS/email напоминания, снижение no-show.
- **Источники:** [yclients.com](https://yclients.com/), [лендинг йога-студии](https://www.yclients.com/yoga_studio).

### Sport Priority

- **Роли в продукте:** личные кабинеты **управляющего**, **администратора**, **тренера**; разные уровни (например «тренер-стажёр» без создания клиентов).
- **Ядро:** расписание (разовые/повторяющиеся слоты, копирование, скрытие слотов от клиентов — аренда/персонал), продажа абонементов из расписания, посещения, расчёт зарплат тренеров, аналитика по клубу/филиалам.
- **Сеть:** несколько залов, разделение прав админов и тренеров в одной CRM.
- **Клиент:** мобильное приложение — бронь, оплата, push, чат с клубом.
- **Источники:** [sportpriority.com/crm](https://sportpriority.com/crm/), FAQ по ролям тренеров.

### Mindbody (международный ориентир)

- **Owner login:** один на сайт, полный контроль; часть настроек (подписка Mindbody, API, маркетинг) — только owner.
- **Permission groups:** Manager, Staff, Front Desk, Instructors, Webmaster; копирование групп для вариаций (например Front Desk + payroll).
- **Типичное разделение:**
  - Owner/Admin — настройки, staff, reports, finances.
  - Manager — расписание, клиенты, операции.
  - Front desk — check-in, продажи услуг/товаров.
  - Instructor — своё расписание, ограниченный admin (часто «только своё» в payroll).
- **Substitute:** отдельное право — назначение замены на класс, assistants на курс.
- **Default launch tab** по группе (инструктор → Classes, менеджер → Dashboard).
- **Источники:** [Staff Management](https://www.mindbodyonline.com/business/staff-management), [Permission groups](https://support.mindbodyonline.com/s/article/203253763-Permission-groups).

### Другие RU CRM (из вакансий)

Вакансии администраторов школ танцев часто перечисляют: **1С:Фитнес**, **Fitbase**, **АльфаCRM**, **Umai**, **ImpulseCRM** — общий паттерн: CRM + Excel/Google Sheets, единая клиентская база, расписание, абонементы, KPI продаж.

## 2. Вакансии администраторов (танцы / йога)

Повторяющиеся **обязанности** (не «сидеть на ресепшене», а **менеджер по работе с клиентами**):

| Зона | Что пишут в вакансиях |
|------|------------------------|
| Входящий поток | Звонки, мессенджеры, соцсети, лично в студии; скорость ответа — KPI |
| Продажи | Пробное → договор → оплата; «довести заявку до оплаченного пробного»; план первичных продаж |
| CRM | Запись на пробные, оплаты, абонементы, **заморозки**, **отработки**; без пропусков в CRM |
| Расписание | Ведение расписания, **контроль аренды залов**, напоминания об оплатах |
| Педагоги | Координация, фиксация отработанных часов |
| Операции | Открытие/закрытие студии, порядок, **касса** |
| Доход | Оклад + % / KPI от продаж |

Примеры: вакансии Балетия, TODES Марьино, TonTakt, «Высота» (сеть филиалов), управляющий студии (1С фитнес + Excel).

**Вывод:** в отрасли «администратор» = ресепшен + продажи + лёгкий back-office; «управляющий» добавляет отчётность, часы тренеров, развитие студии.

## 3. Почасовая аренда и субаренда залов

Паттерны с сайтов студий и агрегаторов (FindSport, MUSbooking, Madison, BolDance, tomrent):

| Тема | Как обычно работает |
|------|---------------------|
| Бронь | Онлайн, за 1–2 месяца вперёд; кратность 1 час; начало в :00 |
| Оплата | **100% предоплата**; без оплаты бронь снимается автоматически |
| Тарифы | Разовый / регулярный / оптовый / фиксированное расписание / «распродажа» (<4 ч до слота) |
| Постоянные | Договор субаренды, **свой ключ**, баланс на счёте |
| Отмена/перенос | <24 ч — удержание 100%; досрочный выход — слот оплачен полностью |
| Время | Начало = **заявленное** в брони, не фактическое; продление по факту если слот свободен |

**Вывод:** аренда — параллельный бизнес-процесс с отдельными актёрами (арендатор, админ зала), правилами денег и доступа; в CRM студии слоты часто **скрыты** от публичной записи.

## 4. Дневной цикл студии (синтез)

Типичный день **смешанной** студии (занятия + субаренда):

1. **До открытия:** проверка расписания, ключи/доступ, уборка, станция на ресепшене.
2. **Утро:** арендаторы, детские группы; check-in, продажи абонементов, звонки.
3. **День:** пробные, записи в CRM, замены преподавателей, счета арендаторов.
4. **Вечер:** пик групп; закрытие, касса, напоминания завтра.
5. **Параллельно:** владелец/управляющий — деньги, зарплаты, маркетинг.

Сущности, которыми оперируют люди (не экраны CRM):

- Лид / заявка → клиент → абонемент / разовый визит
- Слот расписания → занятие → посещение → списание с абонемента
- Бронь зала → предоплата → доступ → уборка
- Смена кассы / оплата → отчёт владельцу
- Часы преподавателя → расчёт выплаты

## 5. Что намеренно не копируем из вендоров

- Бесконечные permission groups как Mindbody (десятки галочек на группу).
- Складской учёт YCLIENTS (косметика/товары) — для MyWay не ядро.
- Два типа входа staff vs consumer (Mindbody): сотрудник может иметь staff login и отдельный consumer account для записи на занятия. В MyWay у каждого человека **свой** `User` (email/пароль), но **без** второго «клиентского» логина — роль в студии через membership (`user_org_roles`), один вход на человека.
