# Тест-кейсы: SUB_TENANT (субарендатор)

Субарендатор арендует залы студии. Основной сценарий — субаренда, свои пропуска, личный кабинет,
обратная связь. Справочники (предметы, залы, биллинг и т.п.) доступны для чтения; записывающие
действия отклоняются бэкендом (403), даже если фронтенд показывает кнопки (**[Доступ/403]**).

Сквозные проверки (`CONV-*`) применимы. Все формы — под `/go/:slug/manage/...`.

---

## Форма: Дашборд тенанта

### TC-SUBTENANT-DASH-01 — [Отображение] Дашборд без блока поддержки
- **Ожидаемый результат:** KPI-карточки и быстрые действия видны; блок «Связь с поддержкой» и входящие — отсутствуют (только OWNER).

## Форма: Субаренда (`/manage/sublease`) — основной сценарий

Эндпоинты: см. `role-owner.md` → Субаренда. Для SUB_TENANT backend **принудительно** проставляет
`subTenantId = текущий пользователь` при создании.

### TC-SUBTENANT-SUB-01 — [Отображение] Доступность и список
- **Ожидаемый результат:** `GET /sublease/bookings`, `.../availability` отрабатывают; таблица слотов/броней соответствует БД.

### TC-SUBTENANT-SUB-02 — [Кнопка][Сохранение] Создание собственного бронирования
- **Шаги:** «Новое бронирование» → Зал, дата/время, Арендатор (себя), Примечания → «Создать».
- **Ожидаемый результат:** `POST /sublease/bookings`; бронь создаётся со статусом `PENDING`, `subTenantId` = текущий пользователь (форсируется бэкендом);
  `totalAmount` = часы × ставка зала; тост «Бронирование создано».
- **Проверка [Сохранение]:** «Изменить» подгружает сохранённые поля; превью цены корректно.
- **Валидация:** даты только в будущем; пустые start/end — ошибка.

### TC-SUBTENANT-SUB-03 — [Кнопка] Редактирование/отмена своей брони
- **Шаги:** «Изменить» у своей PENDING; «Отменить»; «Восстановить» у CANCELLED.
- **Ожидаемый результат:** `PUT .../{id}`, `.../cancel`, `.../restore` отрабатывают; статусы меняются.

### TC-SUBTENANT-SUB-04 — [Доступ/403] Подтверждение / счёт / оплата запрещены
- **Шаги:** попытаться «Подтвердить»/«Снять подтверждение»/«Сформировать счёт»/«Оплатить».
- **Ожидаемый результат:** действия предназначены для OWNER/ADMIN; backend отклоняет (403). Зафиксировать поведение UI.

### TC-SUBTENANT-SUB-05 — [Отображение] Счета субаренды
- **Ожидаемый результат:** вкладка «Счета субаренды» отображает счета (включая выставленные на этого субарендатора) из БД.

## Форма: Пропуска (`/manage/access`) — только свои

### TC-SUBTENANT-ACCESS-01 — [Отображение] Список только своих пропусков
- **Ожидаемый результат:** `usePasses(user.id)` → показаны только пропуска текущего пользователя; колонка «Владелец» скрыта.

### TC-SUBTENANT-ACCESS-02 — [Доступ] Скрытые элементы
- **Ожидаемый результат:** вкладка «Станция / QR» скрыта; кнопки «Отметить оплату»/«Оформить возврат» скрыты.

### TC-SUBTENANT-ACCESS-03 — [Доступ/403] Записывающие действия и журнал
- **Шаги:** попытаться создать шаблон / выдать пропуск / заморозить / отозвать; открыть «Журнал доступа».
- **Ожидаемый результат:** кнопки видны, но backend отклоняет (403); журнал — 403 (только OWNER/ADMIN).

### TC-SUBTENANT-ACCESS-04 — [Доступ/403] Регистрация входа (ресепшн)
- **Шаги:** вкладка «Регистрация входа» → поиск/вход.
- **Ожидаемый результат:** для SUB_TENANT backend исключает доступ к `/access/check-in*` (403).

### TC-SUBTENANT-ACCESS-05 — [Отображение] Деталь своего пропуска
- **Ожидаемый результат:** «Подробнее» показывает QR и метаданные своего пропуска из БД.

## Формы только для чтения / 403

### TC-SUBTENANT-RO-01 — [Доступ] Предметы (только чтение)
- **Ожидаемый результат:** таблица предметов видна; кнопки создания/редактирования/каталога/зачисления отсутствуют; информация = БД.

### TC-SUBTENANT-RO-02 — [Доступ/403] Расписание и помещения/залы
- **Шаги:** открыть «Расписание»/«Залы»; попытаться создать/изменить запись, помещение или зал (в т.ч. копирование/перенос/архив).
- **Ожидаемый результат:** просмотр работает (данные из БД); мутации (`POST/PUT/DELETE`, копирование/перенос/архив) → backend 403.

### TC-SUBTENANT-RO-03 — [Доступ/403] Биллинг
- **Ожидаемый результат:** вкладки и таблицы видны (read-only данные из БД); любые CRUD-действия → 403.

### TC-SUBTENANT-RO-04 — [Доступ] Финансы скрыты
- **Ожидаемый результат:** пункт меню «Финансы» отсутствует; прямой URL → 403 на финансовых эндпоинтах.

### TC-SUBTENANT-RO-05 — [Доступ/403] Экспорт 1С
- **Шаги:** открыть «Экспорт», нажать «Экспортировать».
- **Ожидаемый результат:** страница видна; `POST /export/1c` → 403; тост об ошибке экспорта.

### TC-SUBTENANT-RO-06 — [Доступ] Преподаватели/Ученики (только чтение)
- **Ожидаемый результат:** Alert «У вас только просмотр…»; кнопки приглашения/изменения/удаления отсутствуют; данные = БД.

### TC-SUBTENANT-RO-07 — [Доступ/403] Новости и Заявки
- **Ожидаемый результат:** формы открываются (UI не прячет), но `POST/PUT/DELETE` по новостям/заявкам отклоняются (403).

### TC-SUBTENANT-RO-08 — [Доступ] График админов (только чтение)
- **Ожидаемый результат:** таблица правил видна; кнопок «Добавить правило»/«Удалить» нет (`canManage=false`).

## Форма: Настройки

### TC-SUBTENANT-SET-01 — [Доступ/403] Вкладки настроек
- **Ожидаемый результат:** вкладки Организация/Публичный сайт/Администраторы/Владелец/Безопасность отображаются;
  сохранение по Организации/Публичному сайту/Владельцу отклоняется бэкендом (403); «Администраторы» — только чтение.

- **Шаги:** вкладка «Безопасность» → текущий/новый/подтверждение → «Сменить пароль».
- **Ожидаемый результат:** `POST /auth/change-password` отрабатывает; пароль изменён (проверить входом); тост успеха.

## Форма: Личный кабинет (`/manage/me/*`)

### TC-SUBTENANT-ME-01 — [Отображение] Главная ЛК — только QR
- **Ожидаемый результат:** на главной ЛК видна **только** карточка «Отметиться по QR» (без «Моё расписание» и «График работы»).

### TC-SUBTENANT-ME-02 — [Кнопка] Отметиться по QR
- **Шаги:** «Отметиться по QR» → камера/токен.
- **Ожидаемый результат:** `POST /access/gate/scan` / `POST /access/check-in`; при отсутствии прав по роли — deny-код `UNSUPPORTED_ROLE`
  с понятным сообщением; при валидном пропуске/слоте — вход регистрируется.

### TC-SUBTENANT-ME-03 — [Доступ] График работы недоступен
- **Шаги:** открыть `/manage/me/work` по URL.
- **Ожидаемый результат:** текст «Раздел доступен администраторам и владельцу.»

### TC-SUBTENANT-ME-04 — [Отображение] Моё расписание по URL
- **Шаги:** открыть `/manage/me/schedule` по URL (карточки на главной нет).
- **Ожидаемый результат:** для SUB_TENANT запрос идёт без user-фильтра (неделя организации); данные из БД. Зафиксировать поведение.
