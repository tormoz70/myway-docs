# Тест-кейсы: Гость (неавторизованный) и публичные формы

Роль: посетитель без входа в систему. Доступны лендинг платформы, формы входа/регистрации,
подтверждение email, публичные страницы тенанта и формы заявок. Эти же формы доступны и
авторизованным пользователям (вход/регистрация — с редиректом).

---

## Форма: Вход `/go/login`

Эндпоинт: `POST /api/auth/login` → `AuthTokensResponse` (`accessToken`, `refreshToken`, `user`, `organization`).
Поля: `email` (Input), `password` (Input.Password). Кнопка «Войти», ссылка «Зарегистрироваться».

### TC-ANON-LOGIN-01 — [Кнопка] Успешный вход и редирект по роли
- **Предусловие:** в БД есть активный пользователь с подтверждёнными учётными данными.
- **Шаги:** 1) Открыть `/go/login`. 2) Ввести корректные email и пароль. 3) Нажать «Войти».
- **Ожидаемый результат:** запрос `POST /api/auth/login` возвращает пару токенов; `access_token` и
  `refresh_token` сохранены в `localStorage`; произошёл редирект: `SUPER_ADMIN`/`SUPER_USER` → `/go/platform`,
  пользователь с организацией → `/go/{slug}/manage/dashboard`, иначе → `/go/`.
- **Проверка БД/бизнес-логики:** профиль в ответе (`user.role`, `organization`) соответствует записи в БД;
  при редиректе из `ProtectedRoute` возврат на исходный `state.from.pathname`.

### TC-ANON-LOGIN-02 — [Валидация] Пустые/некорректные поля
- **Шаги:** 1) Оставить email пустым → «Войти». 2) Ввести `not-an-email` → «Войти». 3) Оставить пароль пустым.
- **Ожидаемый результат:** клиентские ошибки «Введите email» / «Некорректный email» / «Введите пароль»;
  запрос на сервер не уходит.

### TC-ANON-LOGIN-03 — [Кнопка] Неверный пароль
- **Шаги:** ввести существующий email и неверный пароль → «Войти».
- **Ожидаемый результат:** 401; тост «Неверный пароль или имя пользователя!» (или текст из API); токены не сохранены.

### TC-ANON-LOGIN-04 — [Доступ] Деактивированный аккаунт / заблокированный тенант
- **Предусловие:** пользователь деактивирован, либо его организация в `blockMode=HARD`.
- **Шаги:** войти под этим пользователем.
- **Ожидаемый результат:** 403 с сообщением «Учётная запись деактивирована» / запрет входа по блокировке тенанта; вход не выполнен.

### TC-ANON-LOGIN-05 — [Кнопка] Сервер недоступен
- **Шаги:** при недоступном backend (502/504/сеть) нажать «Войти».
- **Ожидаемый результат:** тост «Не удалось связаться с сервером…»; кнопка выходит из состояния loading.

### TC-ANON-LOGIN-06 — Переход к регистрации
- **Шаги:** нажать ссылку «Зарегистрироваться».
- **Ожидаемый результат:** переход на `/go/register`.

## Форма: Регистрация студии `/go/register`

Эндпоинт: `POST /api/auth/register` (создаёт `User` роль `OWNER` + `Organization` + `UserOrgRole` + аудит согласий).
Проверка slug: `GET /api/public/organizations/check-slug?value=`.
Поля: `name`, `email`, `password`, `organizationName`, `organizationSlug`, чекбоксы `termsAccepted`/`marketingConsent`.

### TC-ANON-REG-01 — [Кнопка][Сохранение] Успешная регистрация владельца
- **Шаги:** 1) Заполнить имя, email, надёжный пароль (≥8, zxcvbn score ≥ 2), название студии. 2) Принять условия. 3) «Зарегистрироваться».
- **Ожидаемый результат:** в БД создаётся `User` с ролью `OWNER`, `Organization` (name/slug), `UserOrgRole`,
  запись согласия (`acceptedTermsVersion`, `acceptedTermsAt`, `marketingConsent`); приходит письмо подтверждения email;
  выполнен автологин и редирект на `/go/{slug}/manage/dashboard`.
- **Проверка БД/бизнес-логики:** `GET /api/auth/me` после входа возвращает роль `OWNER` и созданную организацию;
  `slug` в БД = нормализованному значению.

### TC-ANON-REG-02 — [Сохранение] Автогенерация slug из названия
- **Шаги:** ввести название студии, не трогая поле slug.
- **Ожидаемый результат:** slug автоматически нормализуется из названия (латиница/цифры/дефис); превью URL `/go/{slug}`.
- **Проверка:** сохранённый в БД slug совпадает с показанным превью.

### TC-ANON-REG-03 — [Валидация] Проверка доступности slug (debounce 350мс)
- **Шаги:** 1) Ввести занятый slug. 2) Ввести slug короче 3 символов / с недопустимыми символами. 3) Ввести свободный валидный slug.
- **Ожидаемый результат:** соответственно ошибки «Этот адрес уже занят» / «Минимум 3 символа…»; для свободного — статус success.
- **Проверка:** запрос `check-slug` отвечает `{ valid, available }` согласно состоянию БД.

### TC-ANON-REG-04 — [Валидация] Слабый пароль и непринятые условия
- **Шаги:** 1) Ввести пароль `1234` → submit. 2) Не отметить чекбокс условий → submit.
- **Ожидаемый результат:** ошибка надёжности пароля; «Необходимо принять условия для регистрации»; регистрация не выполнена.

### TC-ANON-REG-05 — [Кнопка] Дубликат email
- **Предусловие:** email уже существует в БД.
- **Шаги:** зарегистрироваться с этим email.
- **Ожидаемый результат:** 409; тост с сообщением о существующем аккаунте; новая организация не создаётся.

### TC-ANON-REG-06 — [Сохранение] Маркетинговое согласие
- **Шаги:** при регистрации отметить/не отметить чекбокс маркетинга.
- **Ожидаемый результат:** значение `marketingConsent` сохраняется в БД именно в установленном состоянии (проверить через `/api/account/privacy/export`).

## Форма: Подтверждение email `/go/verify-email`

Эндпоинты: `POST /api/auth/verify-email {token}`, `POST /api/auth/resend-verification {email?, captchaToken?}`, `GET /api/auth/captcha-config`.

### TC-ANON-VERIFY-01 — [Кнопка] Подтверждение по валидной ссылке
- **Шаги:** открыть `/go/verify-email?token=<валидный>`.
- **Ожидаемый результат:** автоматическая проверка → состояние «Готово»; в БД у пользователя `emailVerified=true`;
  если пользователь авторизован — флаг в auth-store обновляется.

### TC-ANON-VERIFY-02 — [Отображение] Истёкший / недействительный / отсутствующий токен
- **Шаги:** открыть страницу с истёкшим (TTL 48ч), уже использованным и без токена.
- **Ожидаемый результат:** состояния «Срок действия ссылки истёк» / «Ссылка недействительна» / подсказка; показывается форма повторной отправки.

### TC-ANON-VERIFY-03 — [Кнопка] Повторная отправка письма (гость, с капчей)
- **Предусловие:** `captcha-config.enabled=true` и задан `siteKey`.
- **Шаги:** ввести email, пройти SmartCaptcha, нажать «Отправить ссылку повторно».
- **Ожидаемый результат:** тост «Если аккаунт найден, письмо… отправлено» (без раскрытия наличия аккаунта); `captchaToken` сбрасывается.

### TC-ANON-VERIFY-04 — [Валидация] Повтор без капчи
- **Шаги:** при включённой капче нажать «Отправить» без прохождения.
- **Ожидаемый результат:** предупреждение «Подтвердите, что вы не робот»; запрос не уходит.

### TC-ANON-VERIFY-05 — [Доступ] Неподтверждённый email блокирует запись
- **Связь:** `CONV-EMAIL-UNVERIFIED` в `00-conventions.md`. E2E: `auth-from-manual.spec.ts` (заголовок TC-GEN-003A).
- **Ожидаемый результат:** баннер; `POST/PUT/PATCH/DELETE` отклоняются, пока `emailVerified=false`.

## Форма: Публичная страница студии `/go/:slug`

Эндпоинты: `GET /api/public/organizations/by-slug/{slug}`, `GET /api/public/{slug}/subjects-catalog`.

### TC-ANON-TENANT-HOME-01 — [Отображение] Карточка студии из БД
- **Шаги:** открыть `/go/:slug` валидного активного тенанта.
- **Ожидаемый результат:** заголовок = `name`, описание = `description`, контакты (`contactPhone`, `contactEmail`, `address`) соответствуют БД.

### TC-ANON-TENANT-HOME-02 — [Доступ] Несуществующий/заблокированный тенант
- **Шаги:** открыть `/go/:slug` с неизвестным slug или тенантом `blockMode=HARD`/неактивным.
- **Ожидаемый результат:** UI 404 (страница не найдена).

### TC-ANON-TENANT-HOME-03 — [Выпадающий список] Выбор предмета для заявки преподавателя
- **Шаги:** выбрать предмет в «Предмет из списка (по желанию)» → «Подать заявку преподавателя».
- **Ожидаемый результат:** переход на `/go/:slug/join/instructor?subjectId=<id>`; список предметов = `subjects-catalog` (только `catalogActive`).

### TC-ANON-TENANT-HOME-04 — [Кнопка][Валидация] CTA ученика заблокирована без предмета
- **Шаги:** не выбирать предмет в «Выберите предмет».
- **Ожидаемый результат:** кнопка «Записаться учеником» disabled; после выбора предмета активна и ведёт на `/go/:slug/join/student?subjectId=<id>`.

### TC-ANON-TENANT-HOME-05 — Навигационные карточки
- **Шаги:** кликнуть карточки «Новости», «Преподаватели», «Расписание».
- **Ожидаемый результат:** переходы на `/news`, `/teachers`, `/schedule` соответственно.

### TC-ANON-TENANT-HOME-06 — [Доступ] Карточка «Это ваша студия»
- **Предусловие:** авторизован пользователь, чей `organization.slug` совпадает со slug страницы.
- **Ожидаемый результат:** отображается карточка с кнопкой «В кабинет» → `/go/:slug/manage/dashboard`.

### TC-ANON-TENANT-HOME-07 — [Отображение] Группировка помещений и залов
- **Предусловие:** у помещения есть залы с HTML-описанием или атрибутами (площадь, оборудование).
- **Ожидаемый результат:** на главной студии залы сгруппированы под помещением с подзаголовком «Залы в этом помещении».

### TC-ANON-RENT-01 — [Кнопка] Аренда зала: выбор слота и заявка субарендатора
- **Шаги:** на карточке зала с `hourlyRate` → «Аренда зала» → выбрать дату и свободный слот → «Далее» → заполнить регистрацию.
- **Ожидаемый результат:** `GET /api/public/{slug}/halls/{id}/availability`; `POST /api/public/{slug}/join` с `intent=SUB_TENANT` и полями `rentalHallId`, `rentalStartTime`, `rentalEndTime`; заявка в `/manage/join-requests` с блоком «Аренда зала».

## Формы заявок: `/go/:slug/join/instructor` и `/go/:slug/join/student`

Эндпоинт: `POST /api/public/{slug}/join` (создаёт `User` + `UserOrgRole` + `JoinRequestDetails`, без автологина).
Поля: `name`, `email`, `password`, `subjectIds`, `requestedSubjectNames` (преп.), `message`, согласия.

### TC-ANON-JOIN-INS-01 — [Кнопка][Сохранение] Заявка преподавателя из каталога
- **Шаги:** заполнить имя/email/пароль, выбрать предмет(ы), принять условия → «Подать заявку».
- **Ожидаемый результат:** создаётся `User` + `UserOrgRole` роли `INSTRUCTOR`; статус `PENDING` (если у тенанта
  `publicRegistrationApprovalRequired=true`) или `ACTIVE`; в `JoinRequestDetails` сохранены `intent=INSTRUCTOR`, `subjectIds`, `message`.
- **Проверка:** заявка появляется в «Заявки на вступление» у OWNER/ADMIN с теми же данными.

### TC-ANON-JOIN-INS-02 — [Сохранение] Произвольные названия предметов
- **Шаги:** не выбирать из каталога, ввести названия в «Если нужного предмета нет в списке» (теги) → submit.
- **Ожидаемый результат:** `requestedSubjectNames` сохранены и отображаются в заявке у админа фиолетовыми тегами.

### TC-ANON-JOIN-INS-03 — [Валидация] Ни каталог, ни произвольные имена
- **Шаги:** не выбрать предметы и не ввести имена → submit.
- **Ожидаемый результат:** предупреждение «Выберите предмет из списка или укажите название…»; заявка не отправлена.

### TC-ANON-JOIN-STU-01 — [Кнопка][Сохранение] Заявка ученика
- **Шаги:** заполнить поля, выбрать предмет(ы), принять условия → «Записаться».
- **Ожидаемый результат:** создаётся `UserOrgRole` роли `STUDENT`; `JoinRequestDetails` с `intent=STUDENT`, `subjectIds`.

### TC-ANON-JOIN-STU-02 — [Валидация] Ученик без предмета
- **Шаги:** не выбрать предмет → submit.
- **Ожидаемый результат:** предупреждение «Выберите хотя бы один предмет».

### TC-ANON-JOIN-03 — [Отображение] Экран результата PENDING vs ACTIVE
- **Ожидаемый результат:** `PENDING` → «Заявка отправлена» (кнопка «На страницу студии»); `ACTIVE` → «Регистрация завершена» (+ «Войти»).

### TC-ANON-JOIN-04 — [Кнопка] Дубликат email в заявке
- **Ожидаемый результат:** 409 «Аккаунт с таким email уже существует. Войдите…»; заявка не создаётся.

### TC-ANON-JOIN-05 — [Сохранение] Префилл из URL
- **Шаги:** открыть `/join/student?subjectId=<id>`.
- **Ожидаемый результат:** соответствующий предмет предвыбран в форме.

## Форма: Профиль и приватность `/go/account/privacy`

Эндпоинты: `GET /api/account/privacy/export`, `PATCH /api/account/privacy/marketing {consent}`, `DELETE /api/account/privacy {confirmEmail, reason?}`.
> Доступна только авторизованным (страница рендерится для гостя, но API требует JWT → 401). Удаление недоступно для `OWNER`/`SUPER_ADMIN`/`SUPER_USER`.

### TC-ANON-PRIVACY-01 — [Кнопка] Экспорт данных
- **Шаги (авторизован):** нажать «Скачать мои данные».
- **Ожидаемый результат:** скачивается JSON `myway-account-export-{userId}.json` с данными пользователя из БД; тост «Экспорт ваших данных скачан».

### TC-ANON-PRIVACY-02 — [Кнопка][Сохранение] Отзыв маркетингового согласия
- **Шаги:** нажать «Отозвать маркетинговое согласие».
- **Ожидаемый результат:** `PATCH .../marketing {consent:false}`; в БД `marketingConsent=false` + запись аудита; тост об отзыве.
- **Проверка:** повторный экспорт показывает `marketingConsent=false`.

### TC-ANON-PRIVACY-03 — [Доступ] Кнопка удаления для OWNER/SUPER_*
- **Ожидаемый результат:** для `OWNER`/`SUPER_ADMIN`/`SUPER_USER` кнопка «Удалить аккаунт» disabled + предупреждение.

### TC-ANON-PRIVACY-04 — [Кнопка][Валидация] Запрос на удаление (разрешённые роли)
- **Предусловие:** роль `ADMIN`/`SUB_TENANT`/`INSTRUCTOR`/`STUDENT`.
- **Шаги:** открыть модалку, ввести email не совпадающий с аккаунтом → ошибка; ввести корректный email, причину → «Удалить».
- **Ожидаемый результат:** при несовпадении — «Email не совпадает…»; при корректном — `DELETE`, создаётся `AccountDeletionRequest` (PENDING),
  аккаунт деактивируется, logout через ~1.5с; тост о принятии запроса (обезличивание в течение 30 дней).
- **Проверка:** повторный запрос удаления → 409 «Запрос на удаление уже находится в обработке».
