# Тест-кейсы: SUPER_USER (оператор платформы без управления операторами)

`SUPER_USER` имеет тот же доступ к платформенной консоли, что и `SUPER_ADMIN`, **кроме** вкладки
«Операторы» и создания операторов (`isSuperAdmin(role)` = false). Вкладка по умолчанию — «Профиль».

Для всех совпадающих форм тест-кейсы идентичны соответствующим в `role-super-admin.md` — выполнять их
под учётной записью `SUPER_USER`. Ниже только отличия и обязательные ограничения.

---

## Отличия доступа

### TC-SUPERUSER-OPS-01 — [Доступ] Вкладка «Операторы» скрыта
- **Шаги:** войти как `SUPER_USER`, открыть `/go/platform`.
- **Ожидаемый результат:** вкладка «Операторы» отсутствует; вкладка по умолчанию — «Профиль».

### TC-SUPERUSER-OPS-02 — [Доступ/403] Принудительный `?tab=operators`
- **Шаги:** открыть `/go/platform?tab=operators`.
- **Ожидаемый результат:** активной становится вкладка «Профиль» (operators недоступна); запрос `GET /platform/operators` не выполняется.

### TC-SUPERUSER-OPS-03 — [Доступ/403] Создание оператора через API
- **Шаги:** попытаться вызвать `POST /platform/operators` напрямую под токеном `SUPER_USER`.
- **Ожидаемый результат:** отказ (403) — создание операторов только для `SUPER_ADMIN`.

---

## Совпадающие формы (выполнять как SUPER_ADMIN-кейсы под SUPER_USER)

| Форма | Соответствующие кейсы |
|-------|-----------------------|
| Дашборд платформы | `TC-SUPERADMIN-DASH-01..06` |
| Платформа → Профиль | `TC-SUPERADMIN-PROFILE-01..02` |
| Платформа → Тарифы | `TC-SUPERADMIN-PLANS-01..07` |
| Платформа → Рассылки | `TC-SUPERADMIN-BC-01..03` |
| Платформа → Тенанты | `TC-SUPERADMIN-TENANTS-01..02` |
| Платформа → Подписки и счета | `TC-SUPERADMIN-SUBS-01..05` |
| Платформа → Обращения | `TC-SUPERADMIN-FB-01..02` |
| Обратная связь | `TC-SUPERADMIN-FEEDBACK-01` |
| Доступ к тенант-формам по URL | `TC-SUPERADMIN-ACCESS-01` |

> При прогоне зафиксировать, что все перечисленные формы работают идентично, без появления вкладки/действий «Операторы».
