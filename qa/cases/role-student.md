# Тест-кейсы: STUDENT (студент)

Студент посещает занятия. Собственные действия: своё расписание, свои пропуска, отметка по QR/токену,
обратная связь, приватность. Справочники — только для чтения; мутации отклоняются бэкендом (403).

Сквозные проверки (`CONV-*`) применимы.

---

## Форма: Дашборд тенанта

### TC-STUDENT-DASH-01 — [Отображение] Дашборд
- **Ожидаемый результат:** KPI-карточки и быстрые действия видны; блока поддержки/входящих нет.

---

## Форма: Пропуска (`/manage/access`) — свои пропуска и отметка

### TC-STUDENT-ACCESS-01 — [Отображение] Только свои пропуска
- **Ожидаемый результат:** `usePasses(user.id)` → только пропуска текущего ученика; колонка «Владелец» скрыта; станция/оплата/возврат скрыты.

### TC-STUDENT-ACCESS-02 — [Кнопка] Регистрация входа / отметка
- **Шаги:** вкладка «Регистрация входа» поиск+вход; либо ЛК → «Отметиться по QR».
- **Ожидаемый результат:** для STUDENT backend разрешает `/access/check-in*` и `/access/gate/scan`; вход регистрируется при валидном пропуске/слоте.

### TC-STUDENT-ACCESS-03 — [Доступ/403] Записывающие действия / журнал
- **Ожидаемый результат:** шаблоны/выдача/заморозка/отзыв и «Журнал доступа» → backend 403.

### TC-STUDENT-ACCESS-04 — [Отображение] Деталь своего пропуска
- **Ожидаемый результат:** «Подробнее» показывает QR, сроки, визиты (`visitsUsed/visitsTotal`), статус из БД.
- **Проверка бизнес-логики:** после успешной отметки `visitsUsed` увеличивается; по исчерпании визитов статус становится `USED`.

## Форма: Личный кабинет (`/manage/me/*`)

Эндпоинт: `GET /schedule/entries?from&to&studentId=<user.id>`.

### TC-STUDENT-ME-01 — [Отображение] Главная ЛК
- **Ожидаемый результат:** карточки «Моё расписание» и «Отметиться по QR» (без «График работы»).

### TC-STUDENT-ME-02 — [Отображение] Моё расписание (фильтр по ученику)
- **Шаги:** открыть «Моё расписание», листать недели.
- **Ожидаемый результат:** запрос с `studentId=user.id`; показаны только занятия ученика — и те, куда его добавила студия (состав группы), и те, на которые он записался сам (`lesson_enrollments`); данные из БД.

### TC-STUDENT-ME-05 — [Кнопка][Сохранение] Отмена своей записи
- **Шаги:** записаться на свободное занятие текущей недели («Записаться»), затем «Отменить» в той же строке.
- **Ожидаемый результат:** после записи — метка «Записан» и кнопка «Отменить» в строке занятия; `DELETE /schedule/entries/{id}/enrollments/{enrollmentId}`; при старте меньше чем через 4 часа — предупреждение о поздней отмене.

### TC-STUDENT-ME-03 — [Кнопка] Отметиться по QR / токену
- **Шаги:** «Запустить камеру» → станционный QR; либо ввод токена → «Отметиться».
- **Ожидаемый результат:** `POST /access/gate/scan {raw}` / `POST /access/check-in {qrCodeToken}`; success «Вход/Посещение зарегистрировано»;
  deny-коды (`NO_PASS`/`NO_SLOT`/`INVALID_CODE`/`UNSUPPORTED_ROLE`/…) и rate-limit (429) показываются понятными сообщениями.

### TC-STUDENT-ME-04 — [Доступ] График работы недоступен
- **Ожидаемый результат:** `/manage/me/work` → «Раздел доступен администраторам и владельцу.»

## Формы только для чтения / 403

### TC-STUDENT-RO-01 — [Доступ] Предметы (только чтение)
- **Ожидаемый результат:** таблица видна; нет действий записи; иконка тарифов недоступна (не преподаватель).

### TC-STUDENT-RO-02 — [Доступ/403] Расписание, Помещения/залы, Биллинг, Экспорт
- **Ожидаемый результат:** просмотр работает; любые мутации (в т.ч. CRUD помещений/залов, архив/восстановление) / экспорт → backend 403.

### TC-STUDENT-RO-03 — [Доступ] Финансы скрыты
- **Ожидаемый результат:** меню «Финансы» отсутствует; прямой URL → 403.

### TC-STUDENT-RO-04 — [Доступ/403] Субаренда — создание запрещено
- **Ожидаемый результат:** просмотр доступности/списка работает; создание брони → 403.

### TC-STUDENT-RO-05 — [Доступ] Преподаватели/Ученики (только чтение)
- **Ожидаемый результат:** Alert «У вас только просмотр…»; данные из БД; действий записи нет.

### TC-STUDENT-RO-06 — [Доступ/403] Новости, Заявки
- **Ожидаемый результат:** формы видны; `POST/PUT/DELETE` → 403.

### TC-STUDENT-RO-07 — [Доступ] График админов (только чтение)
- **Ожидаемый результат:** таблица видна; кнопок добавления/удаления нет.

## Семья (родитель → ребёнок)

Эндпоинты: `GET /me/family/children`, записи с `actingAsUserId`.

### TC-STUDENT-FAMILY-01 — [Отображение] Селектор ребёнка на Главной
- **Предусловие:** у студента есть дети в `family_members` (созданы владельцем/админом в профиле клиента).
- **Ожидаемый результат:** карточка «Семья» с Select «Смотреть как ребёнок»; при выборе — расписание и абонементы ребёнка.

### TC-STUDENT-FAMILY-02 — [Сохранение] Запись ребёнка на занятие
- **Шаги:** выбрать ребёнка в селекторе → записать на занятие (actingAs).
- **Ожидаемый результат:** enrollment создан для `actingAsUserId`; guardian может действовать только для своих детей.

---

## Публичные формы (как гость)

Ученик мог быть создан через публичную заявку. Релевантные публичные сценарии — в `role-anonymous.md`:
заявка ученика (`TC-ANON-JOIN-STU-01..02`), публичные страницы студии, вход, подтверждение email.
