# Тест-кейсы: SUPER_ADMIN (оператор платформы)

Полный оператор платформы. Меню сведено к: «Главная» (дашборд платформы), «Платформа», «Обратная связь».
Доступ к `/go/platform` через `RoleGuard(['SUPER_ADMIN','SUPER_USER'])`. Отличие от `SUPER_USER`:
доступна вкладка **«Операторы»** и управление ими (`isSuperAdmin`).

Прочие тенант-формы (расписание, предметы и т.д.) в меню отсутствуют, но открываются по прямому URL
(`ProtectedRoute` пропускает оператора в любой `:slug`). Тенантные мутации, как правило, отклоняются (403).

## Форма: Дашборд платформы (`/go/:slug/manage/dashboard`, ветка оператора)

Эндпоинты: `GET /platform/dashboard/summary`, `/platform/dashboard/top-tenants-by-size`, `/platform/dashboard/tenants`,
`POST /platform/tenants/{id}/message`, `/platform/tenants/{id}/block`, `/platform/tenants/{id}/unblock`.

### TC-SUPERADMIN-DASH-01 — [Отображение] Сводные метрики
- **Шаги:** открыть дашборд, вкладка «Обзор».
- **Ожидаемый результат:** карточки «Всего тенантов», «Участников в студиях», «Учётных записей», «Входов за сутки»,
  «Использовано в БД, Гб», «Лимит БД, Гб (% )» соответствуют `summary` из БД (`totalTenants`, `totalUsers`,
  `totalAccounts`, `totalCheckIns`, `usedDbGb`, `totalDbGb`, `utilizationPercent`).

### TC-SUPERADMIN-DASH-02 — [Отображение] Таблица «Top-10 по входам»
- **Ожидаемый результат:** колонки Тенант (`organizationName`+`organizationSlug`), Регистрация (`registeredAt`),
  Владелец (`owner.fullName`/`email`), Пользователей (`userCount`), Объём (`usedMb`, `storagePercent`),
  Входов за сутки (`dailyCheckIns`), Статус (`blockMode`/`active`) — все из БД.

### TC-SUPERADMIN-DASH-03 — [Отображение] Таблица «Все тенанты»
- **Ожидаемый результат:** как Top-10 + колонки «Размер, Гб» (`usedGb`) и «Действия» (Сообщение/Блокировать/Разблокировать).

### TC-SUPERADMIN-DASH-04 — [Кнопка][Сохранение] Сообщение владельцу
- **Шаги:** в строке тенанта «Сообщение» → ввести Тему (≤255) и Сообщение (≤4000) → отправить.
- **Ожидаемый результат:** `POST /platform/tenants/{orgId}/message`; сообщение сохранено и доставлено владельцу
  (видно во входящих OWNER на дашборде тенанта); тост «Сообщение отправлено владельцу».
- **Валидация:** пустые тема/сообщение блокируют отправку.

### TC-SUPERADMIN-DASH-05 — [Кнопка][Сохранение] Блокировка тенанта
- **Шаги:** «Блокировать» → выбрать режим `SOFT`/`HARD`, причина (≤2000) → подтвердить.
- **Ожидаемый результат:** `POST /platform/tenants/{id}/block`; в БД `blockMode` обновлён; тост «Режим блокировки обновлен».
- **Проверка бизнес-логики:** при `SOFT` владелец может входить, но запись запрещена; при `HARD` вход в тенант запрещён
  (проверить логином пользователя этого тенанта — TC-ANON-LOGIN-04).

### TC-SUPERADMIN-DASH-06 — [Кнопка] Разблокировка
- **Шаги:** «Разблокировать» у заблокированного тенанта.
- **Ожидаемый результат:** кнопка disabled при `blockMode=NONE`; иначе `POST .../unblock`, `blockMode → NONE`, тост «Тенант разблокирован».

## Форма: Платформа → Профиль (`PlatformOperatorAccountTabs`)

Эндпоинты: `PUT /api/auth/profile`, `POST /api/auth/change-password`.

### TC-SUPERADMIN-PROFILE-01 — [Сохранение] Личные данные
- **Шаги:** изменить email/имя/фамилию/телефон → «Сохранить».
- **Ожидаемый результат:** `PUT /auth/profile`; данные сохранены в БД; `authStore.user` обновлён; тост «Профиль обновлён».
- **Проверка [Сохранение]:** F5 → форма подгружает сохранённые значения.

### TC-SUPERADMIN-PROFILE-02 — [Кнопка][Валидация] Смена пароля
- **Шаги:** ввести текущий пароль, новый (≥8, zxcvbn≥2), подтверждение → «Сменить пароль».
- **Ожидаемый результат:** `POST /auth/change-password`; пароль изменён (проверить повторным входом); тост успеха.
- **Валидация:** несовпадение подтверждения / слабый пароль / неверный текущий — отклоняются.

## Форма: Платформа → Операторы (только SUPER_ADMIN)

Эндпоинты: `GET /platform/operators`, `POST /platform/operators`.

### TC-SUPERADMIN-OPS-01 — [Доступ] Вкладка видна только SUPER_ADMIN
- **Ожидаемый результат:** вкладка «Операторы» отображается; для `SUPER_USER` она скрыта, а `?tab=operators` принудительно → `profile`.

### TC-SUPERADMIN-OPS-02 — [Кнопка][Сохранение] Создание SUPER_USER
- **Шаги:** заполнить email/имя/фамилию (пароль опционально, ≥8 если задан) → «Добавить SUPER_USER».
- **Ожидаемый результат:** `POST /platform/operators`; в БД создаётся оператор роли `SUPER_USER`; форма сброшена; тост «Оператор создан».
- **Проверка [Отображение]:** новый оператор появляется в таблице (Email, Имя=`fullName`, Роль-тег, Статус `active`).

### TC-SUPERADMIN-OPS-03 — [Валидация] Обязательные поля / неверный email
- **Ожидаемый результат:** клиентские ошибки; запрос не уходит.

## Форма: Платформа → Тарифы (`PlatformPlansEditor`)

Эндпоинты: `GET /platform/plans`, `POST /platform/plans/{planId}/versions`, `PUT /platform/plans/versions/{versionId}`,
`POST .../versions/{id}/schedule`, `POST .../versions/{id}/cancel-schedule`, `POST .../versions/activate-due`.

### TC-SUPERADMIN-PLANS-01 — [Отображение] Справочник тарифов
- **Ожидаемый результат:** таблица Код (ссылка)/Название/ACTIVE (`v{version} — {monthlyPrice} ₽/мес` или «—») из БД.

### TC-SUPERADMIN-PLANS-02 — [Отображение] Версии выбранного плана
- **Шаги:** кликнуть код плана.
- **Ожидаемый результат:** панель версий: Версия, Статус (DRAFT/SCHEDULED/ACTIVE/ARCHIVED), С/По (`effectiveFrom`/`effectiveTo`),
  ₽/мес, кол-во организаций (`organizationsOnVersion`) — из БД.

### TC-SUPERADMIN-PLANS-03 — [Кнопка][Сохранение] Новая версия из ACTIVE
- **Шаги:** «Новая версия из ACTIVE».
- **Ожидаемый результат:** `POST /platform/plans/{planId}/versions`; создаётся версия `DRAFT` с параметрами активной; список обновляется.

### TC-SUPERADMIN-PLANS-04 — [Кнопка][Сохранение] Редактирование черновика
- **Шаги:** у DRAFT «Изменить» → задать `monthlyPrice` (≥0), `maxUsers` → «Сохранить».
- **Ожидаемый результат:** `PUT /platform/plans/versions/{versionId}`; значения сохранены; тост «Сохранено».
- **Проверка [Сохранение]:** повторное открытие модалки показывает сохранённые `monthlyPrice`/`maxUsers`.

### TC-SUPERADMIN-PLANS-05 — [Кнопка][Сохранение] Планирование версии
- **Шаги:** у DRAFT «Запланировать» → задать `effectiveFrom`, опционально `migrateAllSubscribers` → подтвердить.
- **Ожидаемый результат:** `POST .../schedule`; статус версии → `SCHEDULED`; тост «Версия запланирована».

### TC-SUPERADMIN-PLANS-06 — [Кнопка] Отмена планирования
- **Шаги:** у SCHEDULED «Отменить».
- **Ожидаемый результат:** `POST .../cancel-schedule`; тост «Планирование отменено»; список обновлён.

### TC-SUPERADMIN-PLANS-07 — [Кнопка] Активация запланированных (job)
- **Шаги:** «Активировать запланированные (job)».
- **Ожидаемый результат:** `POST .../versions/activate-due`; info-тост «Активировано версий: N»; due-версии переведены в `ACTIVE`.

## Форма: Платформа → Рассылки (`PlatformBroadcastsPanel`)

Эндпоинты: `GET /platform/broadcasts`, `POST /platform/broadcasts`, `PUT /platform/broadcasts/{id}`, `POST /platform/broadcasts/{id}/send`.

### TC-SUPERADMIN-BC-01 — [Кнопка][Сохранение] Создание черновика рассылки
- **Шаги:** заполнить Название, Тему, коды тарифов (теги), Текст → «Создать черновик».
- **Ожидаемый результат:** `POST /platform/broadcasts` с `audienceType=PLAN_CODE`, `inApp/email=true`; кампания со статусом `DRAFT`; тост «Черновик создан».
- **Проверка [Отображение]:** кампания в таблице (Название/Тема/Статус/Получателей `recipientCount`).

### TC-SUPERADMIN-BC-02 — [Кнопка][Сохранение] Редактирование черновика
- **Шаги:** «Править» у DRAFT → изменить поля → «Сохранить черновик».
- **Ожидаемый результат:** `PUT /platform/broadcasts/{id}`; изменения сохранены; тост «Черновик обновлён».
- **Известный риск:** поле `planCodes` может не восстанавливаться из ответа (там `audienceFilter`) — проверить отдельно.

### TC-SUPERADMIN-BC-03 — [Кнопка] Отправка рассылки
- **Шаги:** «Отправить» у DRAFT.
- **Ожидаемый результат:** `POST .../send`; рассылка уходит получателям выбранных тарифов; тост «Рассылка отправлена»; статус меняется.

## Форма: Платформа → Тенанты и владельцы

Эндпоинт: `GET /platform/organizations`.

### TC-SUPERADMIN-TENANTS-01 — [Отображение] Таблица организаций
- **Ожидаемый результат:** на десктопе первая колонка **«Студия»** (название организации, владелец, slug в одной ячейке); далее **Активность**, **Пользователей**, **Входов в систему**, **Проходов**, **Данные**, **Тариф**, **Статус**, **Email владельца** — из БД. Отдельного заголовка карточки «Организации и владельцы» нет (достаточно вкладки «Тенанты и владельцы»).
- **Мобильный:** вместо таблицы — карточки с теми же ключевыми полями; фильтры в сворачиваемом блоке «Фильтры».

### TC-SUPERADMIN-TENANTS-02 — [Фильтры] Клиентская фильтрация
- **Шаги:** применить фильтры по статусу, тарифу, названию, slug, владельцу, email; затем «Сбросить фильтры».
- **Ожидаемый результат:** список фильтруется корректно (подстрока, без учёта регистра); сброс возвращает полный список.

## Форма: Платформа → Подписки и счета

Эндпоинты: `GET /platform/organizations/{id}/subscription`, `PUT .../subscription`, `POST .../subscription/upgrade-to-active-plan-version`,
`GET/POST .../invoices`, `POST /platform/invoices/{id}/payments`.

### TC-SUPERADMIN-SUBS-01 — [Выпадающий список][Отображение] Выбор организации
- **Шаги:** выбрать организацию в селекторе.
- **Ожидаемый результат:** подгружаются текущая подписка и счета выбранной организации.
- **Известный риск:** форма подписки может не сбрасываться при смене организации (нет `useEffect`) — проверить актуальность значений после смены.

### TC-SUPERADMIN-SUBS-02 — [Кнопка][Сохранение] Назначение подписки
- **Шаги:** выбрать `planCode`, переключатели Trial/Test owner, даты `startsAt`/`endsAt`, `overridePrice` → «Сохранить».
- **Ожидаемый результат:** `PUT .../subscription`; в БД подписка обновлена (план/версия/флаги/цена/даты); тост «Подписка сохранена».
- **Проверка [Сохранение]:** повторная загрузка подписки возвращает сохранённые значения.
- **Валидация:** без выбранной организации — предупреждение «Сначала выберите организацию».

### TC-SUPERADMIN-SUBS-03 — [Кнопка] Перевод на актуальную версию плана
- **Предусловие:** подписка на неактуальной версии (`onActivePlanVersion=false`) — отображается тег «не актуальная».
- **Шаги:** «Перевести на ACTIVE».
- **Ожидаемый результат:** `POST .../upgrade-to-active-plan-version`; подписка на актуальной версии; тост успеха.

### TC-SUPERADMIN-SUBS-04 — [Кнопка][Сохранение] Создание счёта подписки
- **Шаги:** задать сумму (или оставить пусто → цена из версии), период, срок, описание → «Выставить счёт».
- **Ожидаемый результат:** `POST .../invoices`; счёт создан и появляется в таблице; форма сброшена; тост «Счет создан».

### TC-SUPERADMIN-SUBS-05 — [Кнопка] Отметить счёт оплаченным
- **Шаги:** в таблице счетов «Отметить оплачено».
- **Ожидаемый результат:** кнопка disabled для `PAID`; иначе `POST /platform/invoices/{id}/payments` с `source=MANUAL`;
  в БД создаётся платёж/счёт → `PAID`.
- **Известный риск:** отсутствует success/error-тост — подтверждать сменой статуса в таблице после обновления.

## Доступ к тенант-формам по прямому URL

### TC-SUPERADMIN-ACCESS-01 — [Доступ] Открытие тенант-форм по URL
- **Шаги:** перейти по `/go/:slug/manage/schedule`, `/subjects`, `/billing`, `/finance/turnover` и т.п.
- **Ожидаемый результат:** страницы открываются (ProtectedRoute пропускает оператора), но финансовые/тенантные мутации
  отклоняются бэкендом (`financeOwnerOrAdmin()=false` → 403; отчёт оборота показывает Alert об ошибке прав).

## SMTP: рассылка с ящика платформы (ручной, пилот/prod)

### TC-SUPERADMIN-BC-SMTP-01 — Исходящая почта с `PLATFORM_EMAIL_FROM`
- **Тип:** только руками (реальный SMTP, не Playwright).
- **Предусловия:** в `compose.env` настроен рабочий SMTP; OWNER тестовой студии с реальным email; известен код тарифа студии.
- **Шаги:** `/go/platform` → рассылки/чаты с email-копией → черновик по коду тарифа → «Отправить».
- **Ожидаемый результат:** канал EMAIL = `SENT`; письмо от `PLATFORM_EMAIL_FROM` на ящик OWNER; in-app на главной OWNER.
- **При сбое:** логи backend `mail` / `Platform message email failed`.

## eTracker (`/go/etracker/myway`)

Доступ после ограничения модуля — в первую очередь SUPER_ADMIN / SUPER_USER. Проект `MYWAY` из миграции V55.

### TC-SUPERADMIN-ETR-01 — [Кнопка][Сохранение] Создать задачу
- **Шаги:** «Новая задача» → тип, название, описание → сохранить.
- **Ожидаемый результат:** ключ `MYWAY-N`; карточка открывается по ключу.

### TC-SUPERADMIN-ETR-02 — [Кнопка] Комментарий, лайк, подписка
- **Ожидаемый результат:** комментарий в ленте; подписка; один лайк на пользователя; запись в истории.

### TC-SUPERADMIN-ETR-03 — [Кнопка] Взять в работу и трудозатраты
- **Ожидаемый результат:** исполнитель назначен; состояние обновлено; вкладка «Трудозатраты»; история.
